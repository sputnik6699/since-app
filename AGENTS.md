# AGENTS.md — проект «Since»

Учёт событий с датами (подписки, привычки, платежи) в Google-таблице + телеграм-бот + мини-приложение.
Всё, что нужно знать, чтобы продолжить работу без повторного разбора кода.

## 2. Структура таблицы

```
A STATUS | B WHAT | C START | D СРОК | E STOP | F DAYS
```

```js
const COL = { STATUS: 1, NAME: 2, START: 3, TERM: 4, END: 5, DAYS: 6 };
```

Статус в A — **слово**, эмодзи при парсинге игнорируется (`parseStatus` вырезает всё кроме букв), запись всегда в каноническом виде `🍏active` и т.д.

| Статус | Смысл | Что заполнено |
|---|---|---|
| `group` | строка-группа | только A и B; **группа определяется только этим** |
| `🍏active` | классика | C старт, D срок, E стоп (формула), F дни |
| `🍋pause` | пауза | даты **сохраняются**, из сводки исключено |
| `🔢count` | счётчик | только C старт, без срока и окончания |
| `⏳till` | ожидание | только E (дата в будущем), C пуст |
| пусто | не настроено | в сводку не попадает |

F (DAYS) считает **сама таблица** формулой; скрипт только читает `getDisplayValue()` и делает `SpreadsheetApp.flush()` после записи. Знак: `active`/`till` — минус (сколько осталось), `count` — плюс (сколько прошло).

Группы по состоянию на 2026-11-09: Life, Base, Kvn, Ai, Sport.

### ⚠️ Формула у `⏳till` в E (STOP)

```excel
=LET(
  t, TODAY(),
  d, {DATE(YEAR(t),MONTH(t),5); DATE(YEAR(t),MONTH(t),20);
      DATE(YEAR(t),MONTH(t)+1,5); DATE(YEAR(t),MONTH(t)+1,20)},
  p, MAP(d, LAMBDA(x, WORKDAY(x+1, -1, SEQUENCE(8, 1, DATE(YEAR(x),1,1))))),
  MIN(FILTER(p, p>=t))
)
```

Ближайшая Зп. **Скрипт такие ячейки не пишет никогда** — `canWriteEnd(row)` проверяет `getFormula()`, `readStructure` отдаёт флаг `endFormula`. Следствия:
- `/reset` не показывает такие события (сбрасывать нечего);
- мини-апп показывает дату серым с пометкой «формула» и не отправляет `end`;
- при переходе `⏳till` → `🍏active` бот предупреждает заменить формулу в таблице вручную;
- новому `⏳till` из мини-аппа пишется **литеральная дата** (формула не копируется) — открытая задача.

## 3. Архитектура `Code.gs`

**Чтение.** `readStructure()` — единственный источник правды: один проход `getDisplayValues` + `getValues` + `getFormulas` по диапазону `2..lastRow`, возвращает `[{ row, name, status, items: [...] }]`, у item — `row, status, statusText, name, start, startText, term, end, endYmd, endFormula, days`. `getEvents()` — плоский список с `group`/`groupRow`.

**Адресация.** Всё по номеру строки (`callback_data`: `pick:`, `pause:`, `st:`, `sts:`, `set:`, `cal:`, `term:`, `termx:`, `back:`, `noop`, `cancel`), поэтому перед каждой записью — `resolveRow(row, name)` со сверкой имени на случай сдвига.

**Запись.** Все изменения идут через `setDate` / `setTerm` / `setStatus`, каждая пишет и сразу регистрирует правку в `LAST_CHANGE` для `/undo`.

**Undo.** `LAST_CHANGE = { row, name, changes: { start|term|end|status: { from, to } } }`. Правки одной строки склеиваются; `fresh = true` (смена статуса, пауза) начинает новую операцию. Перед откатом проверяется, что текущее значение всё ещё равно `to` — иначе «уже меняли после этого, отменять не стал».

**Коды статусов в callback_data** (лимит Телеграма 64 байта): `a`/`p`/`c`/`t` → `active`/`pause`/`count`/`till`.

**Остальное** — без изменений от исходной версии: `buildDailyMessage` (моноширинные дни, сортировка по `|days|` внутри группы, фильтр `days > MIN_DAYS = -15`), метеограмма через ApiFlash, `clearChatBefore` (удаление диапазонами по 100 id, лимит Телеграма — 48 ч), HMAC-проверка `initData` (`WebAppData`, `auth_date` ≤ 24 ч, владелец = `CHAT_ID`), `LockService` на все изменения из мини-аппа.

### Ловушки

- `nameFromMessage(text)` берёт первую строку сообщения и снимает префиксы `📌` / `✅` / `⏸` — менять тексты `buildPickText` / `buildDoneText` / `buildStatusText` только вместе с этим парсером.
- `addEvent` копирует 1..6 строки-шаблона со сдвигом индекса при вставке строки; шаблон ищется среди событий **того же статуса** (у разных статусов формулы E/F разные), иначе любое событие с формулой в F.
- В сводку идут только `active` / `count` / `till` (`ST_TRACKED`). У `pause` формула F продолжает считать дни (например Москвенок = 38) — это нормально, в чат он не попадает.
- Пустые строки в таблице пропускаются, но группа «запоминается» — события между группами не теряются.

## 4. Мини-апп (`index.html`)

Один файл без сборки: ванильный JS, стили на CSS-переменных Telegram (`--tg-theme-*`), `Telegram.WebApp` для MainButton/BackButton/showAlert/showConfirm. Без `initData` включается **демо-режим** (`DEMO`) с фейковыми группами — удобно проверять вёрстку в обычном браузере.

Экран события — «черновик» `d` (row, name, status, start, end, endText, endFormula, term, days) + `saved` (исходные start/end/term). Переключение статуса перерисовывает только поля, значения забираются `sync()`. Кнопки «Пауза» / «Вернуть в работу» отправляют `saveEvent` с исходными датами, чтобы не сохранять случайные недоделанные правки.

Поля по статусу: `active`/`pause` — старт + срок + итоги; `count` — только старт; `till` — только дата в будущем (или «формула», если `endFormula`).

### API (POST JSON, всегда `{ initData, action, ... }`)

Ответ всех действий: `{ ok, statuses, groups }` (`statuses` — словарь `{active:'🍏active', …}` для кнопок).

| action | Параметры |
|---|---|
| `list` | — |
| `saveEvent` | `row, name, newName, status, start, end, term, group` |
| `addEvent` | `newName, status, start, end, term, group` |
| `deleteEvent` | `row, name` |
| `addGroup` | `newName` |
| `renameGroup` | `row, name, newName` |
| `deleteGroup` | `row, name` (только пустую) |

`start` — для `active`/`count`/`pause`, `end` — для `till` (у остальных игнорируется). Даты — `yyyyMMdd`. Одна правка из мини-аппа = одна запись для `/undo`.

## 5. Команды бота

`/start` `/help` · `/list` (сводка) · `/all` (без фильтра `MIN_DAYS`) · `/reset` (новая дата) · `/status` (смена статуса) · `/pause` (в паузу, даты целы) · `/undo` · `/meteo` · `/app` (кнопка мини-аппа).

Логика `/reset` по статусу: `active` → дата в START + вопрос про срок; `count` → только дата; `till` → дата в STOP (если там не формула); `pause` → дата пишется и статус автоматически становится `active`.

Служебные (запускать из редактора): `setWebhook()`, `getWebhookInfo()`, `checkSetup()` (логирует строки таблицы со статусами + вебхук + тестовое сообщение), `setCommands()` (меню команд, при добавлении команд — прогнать заново), `testMeteogram()`.

## 6. Как работать с этим пользователем

- **Не профессиональный программист**, но деплой Apps Script и GitHub Pages знает сам. **Не расписывать пошаговые инструкции по развёртыванию** — достаточно напомнить: «сделай deploy», «прогони `setCommands()`». Подробности — только если попросит.
- Отвечает по-русски, ценит конкретику и явное перечисление того, что сделано и что осталось.
- Перед правками полезно перечислить, что заметил в коде/таблице (он это использует как ревью).
- Деплой мини-аппа = заменить `index.html` в репозитории; Pages подхватывает сразу. Telegram кэширует страницу мини-аппа — помогает полное закрытие или `?v=2` в `APP_URL`.
